# AI Cloud 开发者研究文档

[English](README.md) | **简体中文**

`devdocs/` 用于保存面向工程实现的研究笔记，为 AI Cloud 的架构和工程决策提供依据。

它与 `docs/` 下的产品需求和稳定架构规范不同：

- `docs/` 定义 AI Cloud 计划构建的正式能力，以及项目承诺维护的契约；
- `devdocs/` 研究外部技术、模型、协议、运行时和工程模式；
- `devdocs/` 中的结论属于研究输入，只有迁移到 ADR、设计文档、API 规范或路线图后，才成为产品承诺。

## 双语文档规范

AI Cloud 的 `devdocs/` 同时维护英文和简体中文版本。

```text
英文兼容入口：<name>.md
中文对应文件：<name>.zh-CN.md
```

维护要求：

1. 英文与中文文件必须具有相同的章节编号和逻辑结构；
2. 表格、代码块、Mermaid 图、配置示例和标识符应保持一致；
3. 事实、数值、许可证条件、限制和引用不得因翻译而发生改变；
4. 每份文档顶部应提供语言切换链接；
5. 修改架构结论时，应在同一个 PR 中同步更新两种语言；
6. 如果暂时无法同步，必须显式标记 `translation-status: pending`，不得默认为已同步；
7. 专有名词首次出现时可采用“中文名称（English Term）”，后文保持统一；
8. 代码、API 字段、环境变量、模型名和文件名不翻译。

## 证据等级

每项研究应区分四类证据：

1. **已发布事实**：官方论文、模型卡、仓库、配置或许可证明确陈述的事实；
2. **代码可验证事实**：可以直接从已发布源码或配置中确认的事实；
3. **工程推断**：基于公开事实作出的合理工程判断，但不是厂商保证；
4. **未知或未验证**：尚未公开、存在歧义或未被独立复现的内容。

## 研究规则

研究文档应：

- 固定观察日期；
- 优先采用一手来源；
- 明确标记厂商报告的 Benchmark；
- 不将开放权重等同于完整开源；
- 记录部署、许可证、来源、评测和运行约束；
- 解释对 AI Cloud 的直接影响，但不得悄然改变产品路线。
