# 00. 研究范围、来源与可信度

[English](00-scope-sources-and-confidence.md) | **简体中文**

## 1. 研究目标

本研究回答五个工程问题：

1. Kimi K3 的端到端技术架构是什么？
2. 哪些内容可以从已发布权重、配置、源码和技术文档中直接观察？
3. 哪些机制是长上下文、稀疏扩展、多模态和 Agent 行为的关键？
4. 训练、推理、评测和运行该模型分别需要什么基础设施？
5. AI Cloud 应如何把 Kimi K3 表示和治理为一个 Provider 与精确模型版本？

## 2. 一手来源

本研究优先采用以下官方来源：

| 来源 | 在本研究中的用途 |
|---|---|
| MoonshotAI/Kimi-K3 GitHub 仓库 | 官方模型概述、部署建议、使用行为、许可证和技术报告 |
| Kimi K3 技术报告，arXiv:2607.24653 | 架构、训练、后训练、基础设施、评测和局限 |
| Hugging Face 上的 moonshotai/Kimi-K3 | 权重清单、配置、自定义 Transformers 实现、Processor 和量化元数据 |
| Kimi K3 License | 权利、Model-as-a-Service 收入门槛、归属门槛、豁免和免责声明 |
| Kimi 官方平台文档 | API 兼容性、推理强度、保留思考历史、工具调用、结构化输出和上下文行为 |

二手 Benchmark 或媒体摘要不作为架构事实的权威来源。

## 3. 证据标签

### 已发布事实

由 Moonshot AI 在官方报告、模型卡、仓库或许可证中直接陈述的内容。

示例：

- 总参数 2.8 万亿；
- 每 Token 激活约 1040 亿参数；
- 93 层；
- 896 个路由专家；
- 每 Token 选择 16 个路由专家；
- 上下文长度 1,048,576 Token。

### 代码可验证事实

可以从已发布配置或实现文件中直接确认的内容。

示例：

- `KimiK3ForConditionalGeneration` 通过自定义 Transformers 代码映射；
- 词表规模约 16 万；
- 模型包含基于 MoonViT 的视觉路径；
- 公开 Checkpoint 被拆分为 96 个 Safetensors 分片；
- 仓库声明了 MXFP4/MXFP8 compressed-tensor 元数据。

### 工程推断

由公开架构推导出的合理工程结论，但不是厂商保证。

示例：

- 约 1.56 TB 的 Checkpoint 使普通单节点部署不现实；
- KDA 与 MLA 混合服务需要两套不同生命周期的缓存；
- 保留推理历史会提高 Trace 敏感度与数据治理要求；
- 极端专家稀疏会把难点从纯算力转移到通信、调度和专家放置。

### 未知或未验证

当前发布材料无法确定的内容。

示例：

- 完整预训练语料；
- 完整数据许可证链；
- 精确样本权重和课程比例；
- 完整训练源码和编排配置；
- 优化器状态和中间 Checkpoint；
- 独立复现的端到端 Benchmark；
- Moonshot AI 生产环境的精确硬件拓扑。

## 4. 公开材料清单

| 工件 | 公开状态 | 说明 |
|---|---|---|
| 完整模型权重 | 已公开 | Hugging Face 上约 1.56 TB，拆分为 96 个 Safetensors 文件 |
| 模型配置 | 已公开 | 架构、Token ID、文本与视觉配置、量化元数据 |
| Transformers 模型实现 | 已公开 | 自定义配置、文本模型、多模态模型、Processor 和媒体工具 |
| 技术报告 | 已公开 | 较详细的架构和系统披露 |
| 许可证 | 已公开 | 自定义 Kimi K3 License，并非 Apache-2.0 |
| 推理配方 | 部分公开 | 官方建议及 vLLM、SGLang、TokenSpeed 等外部引擎配方 |
| 完整预训练源码 | 未确认公开 | 报告描述方法，但仓库不是完整训练栈 |
| 完整训练数据集 | 未公开 | 只披露数据类别与方法 |
| SFT 与 RL 数据集 | 未公开 | 描述环境类别和合成方法，未发布完整语料 |
| Reward Model 和全部奖励函数 | 未公开 | 描述了可验证性与奖励设计，但不能完整复现 |
| 中间 Checkpoint | 未公开 | 发布的是最终模型 Checkpoint |
| 完整官方评测 Harness | 未完全公开 | 许多评测依赖外部 Harness，部分内部套件不可用 |

## 5. 来源版本纪律

本研究是截至 **2026-07-29** 的快照。Kimi K3 刚发布，以下内容可能快速变化：

- 模型仓库文件；
- 推理引擎兼容性；
- 量化内核；
- API 价格和限制；
- 许可证解释指南；
- 独立评测结果；
- 硬件部署配方。

进入生产前，AI Cloud 应固定：

```text
模型仓库
+ 精确 revision
+ 权重 manifest
+ SHA-256 或更强的工件摘要
+ 自定义代码 revision
+ 推理引擎版本
+ 内核版本
+ 许可证 revision
+ 评测套件 revision
```

## 6. 研究局限

本文是架构分析，不是法律意见、独立 Benchmark 报告或硬件容量保证。

技术报告中相对 Kimi K2 的改进，除非已有独立复现，否则均按“厂商报告结果”记录。
