# 07. 与 Kimi K3 的对比

[English](07-kimi-k3-comparison.md) | **简体中文**

## 1. 对比原则

Kimi K3 与 OLMo 3 优化的是不同维度。使用“谁更开放”这样的单一标签，会掩盖真实工程取舍。

|维度|Kimi K3|OLMo 3 / 3.1|
|---|---|---|
|模型规模|2.8T 总参数、约 104B 激活参数的稀疏 MoE|7B 与 32B Dense 模型|
|模态|原生文本与视觉|以文本为主|
|上下文|约 100 万 Token|65,536 Token|
|架构创新|KDA、周期性 Gated MLA、Attention Residuals、极端 MoE|Dense decoder-only Transformer、分阶段训练流程|
|最终权重|公开|公开|
|推理与模型代码|公开自定义代码|公开标准及项目代码|
|预训练数据|未完整发布|发布 Dolma 3 流程|
|中期与长上下文数据|有限披露|发布 Dolmino 与 Longmino|
|后训练数据|有限披露|发布 Dolci 分阶段数据|
|阶段 Checkpoint|相对完整制造流程仍有限|发布主要 Base 与后训练阶段|
|训练代码与配方|方法部分公开，端到端复现不完整|通过 OLMo-core 与 Open Instruct 实现较高开放度|
|许可证|带规模条件的 Kimi K3 自定义许可证|本研究检查的最终 Checkpoint 为 Apache-2.0|
|自托管门槛|极高|32B 较高，7B 明显较低|
|研究价值|前沿稀疏多模态与服务架构|端到端 Model Flow 与可复现性研究|

## 2. 成品、配方与工厂

```text
Kimi K3
成品：高度开放
配方：部分披露
工厂：大部分保留

OLMo 3
成品：开放
配方：高度开放
制造工具链：大部分开放
内部生产运营：仍未完全公开
```

OLMo 3 并没有公开一个机构的全部生产环境。其差异在于模型研发路径被充分暴露，从而允许更深入的复现和分支实验。

## 3. 能力与可检查性

Kimi K3 更适合研究：

- 极端规模稀疏推理；
- 专家并行；
- 原生多模态；
- 百万 Token 系统；
- 专用 Attention Kernel；
- 前沿 Agent 行为。

OLMo 3 更适合研究：

- 数据谱系；
- 训练阶段能力归因；
- SFT/DPO/RLVR 复现；
- Checkpoint Graph 设计；
- 评测配置；
- 开放模型治理；
- 在较早阶段进行低风险实验。

## 4. 部署对比

### Kimi K3

Kimi K3 自托管本身就是一项基础设施工程，需要超大权重存储、分布式专家执行、专用 Kernel、复杂缓存管理和高容量加速器。

### OLMo 3

OLMo 3 7B 可以进入较小的研究和受限部署环境。32B 仍需要较强算力，但比 2.8T MoE 更易接近。

因此，OLMo 3 更适合作为 AI Cloud 自托管 Provider Adapter、谱系 Registry、评测 Runner 和分阶段批准流程的第一验证对象。

## 5. 许可证与来源对比

Kimi K3 自定义许可证需要进行业务规模条件检查。本研究检查的 OLMo 3 最终 Checkpoint 标记为 Apache-2.0，因此模型层权限分析更简单。

但 AI Cloud 仍需分别审查：

- 数据集与来源许可证；
- 代码许可证；
- 推理 Runtime 许可证；
- 衍生模型义务；
- 隐私与区域限制。

宽松模型许可证不等于完整供应链决策。

## 6. 评测策略

先利用 OLMo 3 可见的阶段谱系校准评测系统：

```text
证明 Harness 能识别 OLMo 已知阶段差异
        ↓
将相同固定 Harness 应用于 Kimi K3
        ↓
在不假设隐藏训练细节的情况下解释 Kimi 结果
```

这可以降低评测平台不敏感或配置错误的风险。

## 7. 推荐 AI Cloud 角色

|角色|优先候选|
|---|---|
|开放研究基线|OLMo 3 7B Base|
|后训练研究|OLMo 3 / Tülu 3|
|透明推理路由|OLMo 3.1 32B Think|
|较低成本内部路由|OLMo 3 7B Instruct，需通过评测|
|前沿多模态/MoE 研究|Kimi K3|
|极端长上下文研究|Kimi K3，需严格容量控制|
|治理参考|OLMo 3 Model Flow|

## 8. 战略结论

两者具有互补关系：

```text
OLMo 3 教会 AI Cloud 如何治理一条可见的模型制造流程。
Kimi K3 用于检验：当大量制造过程不可见、服务系统复杂得多时，这套治理是否仍然有效。
```

成熟的 AI Cloud 需要同时保留两条研究路线。
