# AI 演进判断：从智能体走向受治理的持续学习

> 状态：战略研判，尚非已接受的架构契约  
> 证据截止日期：2026-08-28  
> 范围：AI Cloud 路线图与企业架构映射

## 1. 核心结论

原有演进判断在方向上约有 **80% 的准确度**，但不应理解为严格依次发生的阶梯。

其中最有价值的判断是正确的：

1. 前沿模型与推理能力已经跨越若干重要能力阈值；
2. 受治理的智能体是企业当前最务实的投入方向；
3. 无法从企业任务中形成持久学习，是智能体难以替代完整员工角色的重要原因；
4. 企业级持续学习首先是组织记忆与评估闭环问题；
5. 长期竞争最终取决于成本、完成时间、可靠性与用户体验。

需要做三项修正：

- 推理或思维链并不是独立于语言模型、已经彻底完成的一层，而是正在被模型系统吸收的测试时计算与控制机制。
- “模型已经超过人类”只适用于大量定义清晰、上下文充分、结果可验证的任务，并不等于全面超过人类工作。
- AI 辅助研发、自我改进与具身智能已经在受限场景中并行推进，并不会等待一个统一的持续学习突破后才开始。

## 2. 基于当前证据的阶段判断

| 原判断阶段 | 截至 2026-08-28 的证据 | 校准结论 | 对 AI Cloud 的含义 |
| --- | --- | --- | --- |
| 语言模型 | GPT-5.4 在定义清晰的 GDPval 知识工作产物比较中，83% 与行业专业人员持平或更优；GPT-5.6 在 Agents' Last Exam 上达到 53.6。但开放式工作的能力仍然高度不均衡。 | 部分跨越，不能表述为全面跨越 | 将模型视为可替换的能力供应方，而不是自治员工 |
| 推理 / CoT | 增加推理预算能够显著改善困难任务表现；METR 在部分长时程评测中发现，关闭推理后会出现明显能力差距。 | 已成为主流能力放大器，但不是已经结束的独立阶段 | Registry 与 Router 必须显式建模推理预算、延迟、成本与验证；不得把隐藏思维链定义为平台契约 |
| Agent | 前沿系统已经能够规划、调用工具、操作计算机、生成专业产物并持续执行长任务；但在高隐性上下文、目标模糊、依赖社会协作或难以自动验证的工作中，可靠性仍明显下降。 | 当前产品化主战场 | 继续优先建设 Task、Workflow、Agent Runtime、Tool Gateway、Policy、Sandbox、Trace 与 Evaluation |
| 持续学习 | 外部记忆、制品、摘要、测试与检索已经可以维持跨会话连续性；模型内部的持续学习仍属于活跃研究方向，尚未成为成熟的生产能力。 | 正确识别为下一项平台瓶颈 | 先建设受治理的组织记忆，再考虑生产环境在线修改模型权重 |
| 自我迭代 | AlphaEvolve 与 AI co-scientist 已能在存在强自动评估器的领域生成、评估并改进候选方案。这属于受边界约束的优化，不是无约束的递归自我改进。 | 已在窄领域开始 | 建立“提出—评估—晋升”循环，并保留人工与策略闸门 |
| 具身智能 | 机器人系统已能执行持续数分钟、包含数百次决策的多步骤物理任务，但速度、灵巧度、安全、适应性与部署经济性仍是约束。 | 并行分支，而非最后才出现的阶段 | 保留执行适配器边界，使未来物理控制器接入时无需改变 Task 与 Policy 契约 |

METR 给出的外部校准尤其重要：其任务时程评估主要集中在软件工程、机器学习和网络安全；现有任务集中超过 16 小时的测量仍不可靠；即使达到八小时任务时程，也不意味着可以自动化整个岗位，因为真实工作包含隐性知识、人际互动和模糊的成功标准。

## 3. 修正后的演进模型

更准确的表达不是单向阶梯，而是带反馈飞轮和并行分支的能力系统：

~~~mermaid
flowchart TD
    A["基础模型"] --> B["推理与工具使用"]
    B --> C["受治理的智能体"]
    C --> D["组织记忆"]
    D --> C
    C --> E["受边界约束的 AI 研发"]
    C --> F["具身智能体"]
    E --> B
~~~

其中真正产生复利的核心循环是：

~~~text
企业数据与规则
-> 受治理的任务执行
-> 结果、反馈与评估
-> 经过治理的组织记忆
-> 更好的路由、工作流、工具与上下文
-> 以更低任务总成本获得更高成功率
~~~

这比等待一个能够在每次交互后自行修改权重的基础模型更现实。

## 4. 企业级持续学习的准确含义

企业持续学习必须拆成两个层次。

### 4.1 系统级学习：今天即可建设

系统无需改变模型权重，也可以通过版本化和复用以下信息持续改进：

- 任务结果与执行轨迹；
- 被接受的决策及其证据；
- 失败方案与失败原因；
- 经批准的纠正与人工反馈；
- Prompt、Workflow、Tool、Policy 与 Runbook；
- 场景化评估用例；
- 路由质量、延迟、人工介入和总成本历史；
- 带来源信息的可复用制品与领域知识。

这就是 **组织记忆**。它可以实现审计、撤销、迁移和供应商中立，并与现有 AI Cloud 架构兼容。

### 4.2 模型级持续学习：仍在形成

模型级持续学习，是在系统运行过程中更新模型内部参数或持久化的学习记忆。Titans、MIRAS、Nested Learning 等研究已经展现可信进展，但生产应用仍面临：

- 灾难性遗忘与行为回归；
- 反馈投毒和低质量经验污染；
- 隐私、租户隔离与删除义务；
- 可复现性下降；
- 评估和回滚困难；
- 学习后行为的归属和责任不清；
- 企业知识被吸收到单一模型后造成供应商锁定。

因此，AI Cloud v0.1 **不得**把无控制的在线权重更新纳入生产路径。模型适配应保持离线、版本化、经过评估和准入，并且能够回滚。

## 5. AI Cloud 新能力提案：学习与组织记忆平面

这是供后续架构评审的战略提案，不改变已经接受的 S0 契约。

### 5.1 核心职责

该平面应当：

1. 从 TaskEvent、Trace、AuditEvent、CostEvent、Evaluation、人工审批和制品输出中捕获记忆候选；
2. 将其分类为情景记忆、语义记忆、程序记忆或评估记忆；
3. 执行租户、项目、隐私、安全、保留期限与来源治理策略；
4. 对记忆进行去重、评分、过期、替代和撤销；
5. 只在当前 Task 与授权范围内检索相关证据；
6. 量化检索到的记忆是否改善成功率、成本、延迟或人工介入率；
7. 将验证后的经验晋升为知识、工作流、策略、评估用例或路由证据；
8. 保留完整的审计与回滚路径。

### 5.2 记忆类型

| 记忆类型 | 示例 | 主要责任模块 |
| --- | --- | --- |
| 情景记忆 | 任务历史、执行尝试、失败、决策、制品 | Task / Trace |
| 语义记忆 | 企业事实、系统拓扑、术语与约束 | Knowledge / Data |
| 程序记忆 | 工作流、运行手册、工具序列、Prompt、恢复程序 | Workflow / Tool |
| 评估记忆 | 测试用例、结果标签、人工纠正、回归证据 | Evaluation |
| 经济记忆 | 路由成本、重试、延迟、人工介入、成功任务成本 | FinOps / Router |

### 5.3 候选契约

后续设计应定义供应商中立的契约，例如：

- `MemoryRecord`；
- `ExperienceCandidate`；
- `RetrievalEvidence`；
- `LearningEvaluation`；
- `PromotionDecision`；
- `MemoryPolicy`。

每条持久记忆至少应包含：租户与项目范围、来源 Task 与 Trace、记忆类型、来源信息、内容或制品摘要、置信度、责任人、生命周期状态、有效期、替代关系、策略标签、评估证据与审计引用。

### 5.4 强制边界

- 原始生产交互不得直接成为可信组织知识。
- 不得把隐藏思维链作为必须保存的证据对象；应保存计划、动作、工具输入输出、可验证证据和简明决策理由。
- 记忆读取与写入都必须经过 Policy 和租户范围检查。
- 每条记忆必须可以撤销、过期、被新版本替代，并能追溯到来源。
- 记忆晋升必须通过与场景相关的评估和回归闸门。
- Provider 或 Model 迁移不得造成组织记忆丢失。
- Router 可以消费经过验证的经验，但不得突破 Policy、Residency、License、Security 与 Hard Budget 约束。

## 6. 成功指标

学习闭环应以业务任务结果衡量，而不是以记忆数量衡量：

- 重复任务成功率提升；
- 每个成功任务的人工介入次数下降；
- 已知失败重复发生率下降；
- 新企业场景的达到胜任时间；
- 检索准确率与可测量的记忆效用；
- 同类任务重复执行后的成功任务成本；
- 回滚率、撤销率与知识污染率；
- 企业行为跨模型迁移能力；
- 能够通过证据完整重建的决策比例。

最重要的复利指标是：

~~~text
第 N 次执行时的成功任务成本
~~~

有效的组织记忆系统应当使同类任务随着 N 增加而更可靠、更便宜，同时不降低治理标准。

## 7. 路线图决策

AI Cloud 当前的优先级仍然正确：先建设受治理的智能体，再扩大自主性。

建议顺序：

1. 完成现有 Task、Workflow、Agent、Tool Gateway、Policy、Sandbox、Trace、Evaluation 与 Cost 基础；
2. 定义组织记忆威胁模型和供应商中立契约；
3. 从现有 append-only 事件产生记忆候选，但不改变这些事件的事实源职责；
4. 先实现带来源和租户范围的只读检索；
5. 增加由评估驱动的晋升、替代、过期与撤销；
6. 将验证后的记忆用于上下文组装、工作流选择、路由证据与失败预防；
7. 只有在外部学习闭环可测量且稳定后，才考虑离线模型适配；
8. 将模型内部持续学习作为独立版本、独立评估和独立准入的能力。

这延续了已经冻结的原则：Provider、Model Registry 与 Router 不绑定任何单一模型厂商。企业学习能力应主要属于 AI Cloud，而不是被封装在不透明的供应商模型中。

## 8. 进展预测

| 从 2026-08-28 起的时间范围 | 预测 | 置信度 |
| --- | --- | --- |
| 0—18 个月 | 受治理的外部记忆、持久化 Agent 交接、评估驱动的工作流改进和角色型 Agent 将成为企业标准架构 | 高 |
| 18—36 个月 | 在工具、数据和验收标准明确的领域，Agent 将以更低监督承担更大比例的岗位任务切片 | 中高 |
| 3—5 年 | 外部组织记忆与更快的模型内部适配将形成混合系统，但大多数受监管企业仍会保留晋升和回滚闸门 | 中低 |
| 已经开始 | 在具备强自动评估器的领域进行 AI 辅助研发和受边界约束的自我改进 | 高 |
| 时间仍无法可靠判断 | 广义递归模型自我改进，以及在非结构化环境中普遍替代具体人力的通用具身智能 | 低 |

因此，这套判断适合作为战略方向，但不适合作为确定性的阶段顺序或精确时间表。
