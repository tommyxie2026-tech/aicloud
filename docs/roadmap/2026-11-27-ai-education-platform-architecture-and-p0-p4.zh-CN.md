# aicloud 可扩展 AI 教育平台：产品架构与 P0–P4 实施路线

> 决策日期：2026-11-27  
> 已确认方向：不同水平学习者；MIDI + 音频双路线；基于 aicloud 的可扩展 AI 教育平台。  
> 首个垂直场景：AI Piano Tutor（钢琴智能陪练）。  
> 状态：产品与技术路线基线，需通过阶段实验验收；不是已完成能力声明。

## 1. 产品定位与目标

项目不以“音频转 MIDI 工具”为最终目标，而是以钢琴为首个垂直场景，建立可复用的 AI 学习、能力评价和个性化训练平台。

产品目标：
1. 理解学习目标和标准答案（钢琴场景为乐谱/MusicXML）。
2. 获取学习者的实际表现（钢琴场景为 MIDI 或音频识别结果）。
3. 将实际表现与目标进行对齐，定位差异。
4. 根据证据区分识别不确定性、操作错误和技能薄弱点。
5. 形成可解释的能力评价和学习者画像。
6. 生成下一步练习，并通过后续表现验证练习是否有效。
7. 将学科能力、数据、模型、评价和训练流程沉淀为可复用的平台能力。

**钢琴是第一个验证域；通用资产是学习评价闭环，而不是钢琴专用模型本身。**

首期覆盖不同水平学习者：初学、初中级、中高级。系统必须按学习者当前曲目、技能目标和历史表现调整评价尺度，不能用同一套难度阈值评价所有人。

## 2. 产品范围与边界

### 2.1 首期输入

| 输入 | 支持方式 | 处理结果 |
|---|---|---|
| 数字钢琴 MIDI | 文件导入；后续设备实时接入 | 可信音符、时值、力度、踏板事件 |
| 数字钢琴音频 | 线路/耳机输出或录音 | AMT 音符事件；与 MIDI 参考交叉验证 |
| 传统钢琴音频 | 麦克风录音 | AMT 音符事件；低置信度需复核 |
| 乐谱图片/PDF | 图片上传 | OMR 识别结果、MusicXML/Score IR |
| MusicXML/MIDI 乐谱 | 文件导入 | 标准化目标音符事件 |

数字钢琴优先同时采集 MIDI 和音频：MIDI 作为演奏事件参考，音频用于验证 AMT。传统钢琴没有原生 MIDI 时，音频识别结果必须保留置信度，并通过人工核验子集评估。

### 2.2 首期产品功能

- 曲目/乐谱导入与校正；
- 练习会话创建、录制和回放；
- MIDI 或音频演奏分析；
- 乐谱与演奏对齐；
- 错音、漏音、多音、重复音、节奏和时值偏差定位；
- 小节级和音符级报告；
- 学习者能力档案与练习历史；
- 针对错误的局部练习建议；
- 教师/学习者查看评价证据、修正识别错误；
- 练习结果进入学习进展记录。

### 2.3 首期不承诺

- 不承诺所有乐器、所有乐谱版式均可自动识别；
- 不把模型置信度等同真实正确率；
- 不把音频推断的力度、踏板和演奏表现作为确定性结论；
- 不在离线识别尚未通过验收前承诺实时低延迟纠错；
- 不从零训练大型多模态模型；
- 不把 LLM 的自然语言评价作为音符级独立证据。

OMR、MIDI 解析、AMT、对齐和教学反馈是不同职责，必须保持模块边界和可独立评测能力。

### 3.3 学科插件接口

每个学科能力包实现统一业务契约，但保留自身领域模型：

| 契约 | 作用 |
|---|---|
| InputAdapter | 接收图片、音频、MIDI、文本或交互数据 |
| TargetRepresentation | 表示标准答案、学习目标或任务约束 |
| EvidenceRepresentation | 表示学习者实际表现及其来源 |
| Alignment/Comparison | 比较目标与实际表现 |
| ErrorTaxonomy | 领域错误分类及严重度 |
| Evaluator | 根据证据计算可解释评价 |
| LearnerStateAdapter | 将结果映射到通用学习者画像 |
| PracticePolicy | 根据能力缺口生成练习 |
| FeedbackRenderer | 将结构化结果呈现给学习者/教师 |

钢琴插件定义音符、节拍、小节、声部等；英语插件定义音素、单词、流利度等；数学插件定义步骤、定理、推理链等。aicloud 核心只管理通用任务、数据、模型、执行、评价和治理，不固化这些领域字段。

### 3.4 通用学习数据模型

建议统一核心实体：
- Learner：学习者标识与授权；
- LearningObjective：课程/曲目/任务目标；
- Skill：技能及先修关系；
- Session：一次学习或练习会话；
- Evidence：原始表现、模型输出或人工核验结果；
- Error：有证据支持的错误实例；
- Assessment：能力评价及置信度；
- LearnerProfile：随时间变化的能力状态；
- PracticePlan：练习目标、内容、难度和停止条件；
- Progress：阶段性变化；
- Review：教师/人工复核记录。

所有评价必须关联 Evidence、Evaluator 版本和规则/模型版本。模型无法确定时应返回 uncertain/review_required，不得把不确定结果直接记成学习者错误。

## 4. 钢琴模块技术选型

| 子模块 | 第一阶段方案 | 选择原则 |
|---|---|---|
| OMR | Audiveris 基线，人工校正 MusicXML | 先验证目标谱面类型；审查 AGPL-3.0 集成边界 |
| AMT | Basic Pitch 轻量基线；ByteDance Piano Transcription 隔离复现对照 | 不把单一模型当最终方案；分别审查代码、权重、数据许可 |
| MIDI | pretty_midi / mido | 保留原始事件与 tempo/tick 信息 |
| Score IR | MusicXML + music21 解析 | 规范化目标音符、节拍、小节、声部 |
| Alignment | 音符候选匹配 + 动态规划；必要时 DTW 辅助 | 可解释、可测试、容忍整体速度变化 |
| Evaluation | 确定性规则和事件级指标 | 先建立可复现评价，再考虑学习型评分 |
| Practice | 规则策略起步，LLM 只负责解释/表达 | 练习内容须与已验证错误证据关联 |

模型、数据集和运行时的许可证分别登记。MAESTRO 的 CC BY-NC-SA 4.0 不应默认用于商业训练或商业产品；商业数据闭环必须以自采、明确授权或许可兼容数据为基础。

## 5. P0–P4 实施路线

路线调整为：先验证全链路关键技术，再建设可持续数据，再交付完整钢琴陪练，再平台化，最后做自主训练和个性化优化。阶段可以并行准备，但不能跳过验收门槛。

### P0 — 技术可行性与可复现基线

**目标：证明各关键输入路径能被处理，并确定可用基线。**

工作项：
1. 固定隔离的 Python/音频实验环境；
2. 跑通 Basic Pitch 本地音频转 MIDI；
3. 隔离验证 ByteDance 钢琴专用 AMT（若旧依赖/权重可合法、安全获取）；
4. 跑通数字钢琴 MIDI 解析；
5. 跑通 Audiveris 图片/PDF 到 MusicXML 的最小样本；
6. 定义 Piano Event IR、Score IR 和 provenance；
7. 用小型样本验证事件匹配与基础错误分类；
8. 建立许可证清单和实验记录格式。

交付：
- 可复现环境和运行脚本；
- AMT/OMR/MIDI 三条基线结果；
- 统一事件 schema；
- 典型失败案例；
- 初始指标报告；
- 数据/模型/代码许可台账。

验收：
- [ ] 至少一段有使用权的真实钢琴 WAV 可成功推理并生成可打开的 MIDI；
- [ ] 至少一份数字钢琴 MIDI 可解析，音符数、音高、起止事件与源文件一致；
- [ ] 至少一张目标范围内乐谱图片可转成 MusicXML，并完成抽样人工核验；
- [ ] 对已知目标与演奏事件的测试样例，错音、漏音、多音和时间偏差分类结果符合预期；
- [ ] 所有输出记录模型/软件版本、输入哈希、命令和环境；
- [ ] 未验证的真实录音准确率、GPU 性能和数据集可用性明确标记为未知。

P0 不以 GitHub CI 通过替代真实音频推理验收。CI 只证明代码和测试可执行，不证明识别质量。

### P1 — 双路线数据采集与基准体系

**目标：建立可持续、可追溯、可用于训练和独立评价的数据资产。**

工作项：
1. 数字钢琴同步采集 MIDI、音频、曲谱；
2. 校准 MIDI/音频链路延迟，分别记录线路输出、耳机输出和麦克风；
3. 采集传统钢琴音频，并建立人工核验的音符事件子集；
4. 采集不同学习水平、速度、力度、曲目难度和演奏错误；
5. 建立曲谱图片/PDF 与校正 MusicXML 的对应关系；
6. 建立数据 manifest、匿名化 performer/session ID、授权和保留策略；
7. 按演奏者、曲目和录音会话分组划分 train/validation/test，防止泄漏；
8. 建立标注指南和双人抽检/争议处理机制。

交付：
- 数字钢琴配对数据集；
- 传统钢琴人工核验测试集；
- 乐谱/MusicXML 数据集；
- 数据版本、授权和同步校准报告；
- 固定 benchmark split 和评测脚本。

验收：
- [ ] 每条样本具有唯一 ID、来源、设备、采样率、声道、时间信息和授权状态；
- [ ] 数字钢琴 MIDI/音频同步误差经过测量，校准值和波动可追溯；
- [ ] 传统钢琴测试集有人工核验参考，且标注者和复核状态可追溯；
- [ ] 数据划分按 performer/piece/session 分组，无明显泄漏；
- [ ] 原始数据、派生数据、模型预测和人工修订分层存储；
- [ ] 未授权数据不得进入训练集或对外分发。

### P2 — 完整钢琴智能陪练 MVP

**目标：完成从乐谱和演奏输入到可解释评价、个性化练习建议的端到端产品闭环。**

工作项：
1. 曲谱上传、OMR、MusicXML 校正；
2. MIDI 导入和音频上传/录制；
3. AMT 与 MIDI 事件统一化；
4. Score Alignment 和局部速度适配；
5. 错音、漏音、多音、重复音、起音/时值偏差分类；
6. 识别置信度与人工复核入口；
7. 按学习水平、曲目难度和学习目标调整评价规则；
8. 生成小节级、音符级报告；
9. 根据错误证据生成局部练习；
10. 保存学习历史和能力变化。

交付：
- 可操作的钢琴陪练 MVP；
- 完整练习会话和报告；
- 识别/评价接口；
- 练习建议策略；
- 端到端回归测试和用户试用报告。

验收：
- [ ] 乐谱、MIDI、音频三类输入均可完成端到端处理；
- [ ] 报告能定位到小节/音符，并显示目标值、实际值、偏差和来源；
- [ ] 对人工构造的错音、漏音、多音、重复音、抢拍/拖拍用例有确定性测试；
- [ ] 低置信度识别不会被直接标记为学习者错误；
- [ ] MIDI 路线与音频路线的差异可被报告；
- [ ] 不同学习水平使用不同的目标和评价阈值，规则可追溯；
- [ ] 练习建议必须引用已识别的技能缺口和证据；
- [ ] 一次练习结果可保存、回放、复评和比较。

P2 的“完整”指完整的离线练习闭环；实时低延迟陪练作为后续优化，不用未经验证的实时能力替代离线正确性。

### P3 — aicloud 集成与通用教育能力沉淀

**目标：将钢琴 MVP 接入 aicloud，并验证学科插件模式可复用。**

平台职责：
- Dataset Registry：数据集、版本、授权和 lineage；
- Job/Execution：预处理、批量推理、训练、评估任务；
- Artifact Registry：输入/输出、日志、模型和报告产物；
- Model Registry：模型版本、依赖、量化、部署信息；
- Independent Evaluation：固定测试集、回归、质量门禁；
- Policy/Authorization：用户授权、数据用途、模型许可、访问控制；
- Deployment Profile：CPU/GPU/边缘设备运行规格；
- Router：按任务和质量/成本/延迟策略选择模型或处理链；
- Audit/Trajectory：记录数据、模型、执行、评价和反馈链路。

钢琴应用负责 OMR/AMT、音乐语义、事件对齐、演奏评价和练习策略；aicloud 负责可治理的任务执行和模型生命周期，不将钢琴字段固化进平台核心 API。

交付：
- 钢琴垂直应用接入 aicloud 的标准工作流；
- 学科插件接口和 schema；
- 数据、任务、模型、评价的可追溯链路；
- 权限/授权和数据保留策略；
- 第二个学科插件的概念验证（建议英语发音或数学步骤评价，先做小范围验证）。

验收：
- [ ] 钢琴任务能通过 aicloud 创建、执行、查询状态和获取产物；
- [ ] 数据集、模型、执行环境、Evaluator 和报告具有不可混淆的版本；
- [ ] 模型升级必须通过独立评价门禁；
- [ ] 任务失败、重试、取消、超时和产物归档行为可验证；
- [ ] 权限、授权、审计和数据保留策略生效；
- [ ] 钢琴业务字段不污染 aicloud 通用核心模型；
- [ ] 至少一个第二学科插件可复用相同平台生命周期接口，证明抽象不是钢琴特例。

### P4 — 可控训练、个性化和持续优化

**目标：用经过授权和核验的数据提升模型及教学策略，形成可回滚的持续改进闭环。**

工作项：
1. 对比现成 AMT/OMR 基线，定位真实数据域差异；
2. 先做数据增强、阈值校准和轻量微调，再评估蒸馏/量化；
3. 建立 Teacher/Student 和模型压缩实验；
4. 按数字钢琴、传统钢琴、不同设备和学习水平分层评价；
5. 建立学习者长期技能状态与练习效果跟踪；
6. 将教师审核后的样本纳入下一数据版本；
7. 独立测试通过后才晋级 Model Registry；
8. 在离线指标稳定后，再开发流式 AMT、增量对齐和实时反馈。

交付：
- 可复现训练/微调流水线；
- 训练数据 lineage 和实验报告；
- 专用模型候选及与基线对比；
- 个性化练习策略评估；
- 模型晋级、回滚和回归流程；
- 实时陪练原型（如离线质量和延迟预算允许）。

验收：
- [ ] 训练数据来源、许可、过滤、人工复核和版本可追溯；
- [ ] 新模型在独立 holdout 上相对基线有可重复的改善，且没有关键分层回退；
- [ ] 分设备、分学习水平、分曲目难度报告准确率和不确定性；
- [ ] 训练和评估使用不同数据划分，禁止测试集回流；
- [ ] 模型晋级必须经过 Independent Evaluation；
- [ ] 训练失败、模型回滚和数据版本回滚可演练；
- [ ] 个性化练习效果通过前后测或对照试验验证，不能只以使用时长作为效果；
- [ ] 实时功能报告端到端延迟、识别质量和错误反馈率。

## 6. 统一评价方法

### 6.1 识别层

AMT：
- Note Precision / Recall / F1；
- Onset Precision / Recall / F1；
- Offset 指标；
- Velocity MAE（有可靠参考时）；
- Pedal F1（有可靠参考时）。

OMR：
- 音符音高识别准确率；
- 时值/节奏识别准确率；
- 小节线、调号、拍号识别准确率；
- MusicXML 结构有效率；
- 人工校正比例。

### 6.2 对齐与评价层

- Pitch Error Rate；
- Missing Note Rate；
- Extra Note Rate；
- Onset Deviation；
- Duration Deviation；
- Tempo/Local Timing Deviation；
- Measure Localization Accuracy；
- Low-confidence / Review-required Rate；
- 识别错误被误判为学生错误的比例。

起音 50ms 可作为初始实验容差之一，但最终需报告容差曲线，并遵循选定基准的定义。P0/P1 先建立真实基线，再确定正式质量阈值，不预先捏造准确率目标。

### 6.3 教学效果层

- 同类错误的重复发生率；
- 针对性练习后的技能改善；
- 练习建议采纳率；
- 学习者/教师对反馈正确性的评价；
- 不同水平学习者的分层效果；
- 错误反馈的误报率和漏报率。

教学效果需要真实学习数据或设计合理的对照实验支持，不能由模型自评替代。

## 7. 关键技术原则

1. **双路线但统一语义**：MIDI 和音频各自处理，汇聚到统一 Piano Event IR。
2. **识别与评价解耦**：识别模型负责提出事件，评价器负责比较证据。
3. **确定性优先**：音符和节奏差异先用可解释算法，LLM 负责解释和交互。
4. **不确定性显式化**：低置信度、识谱错误和录音质量问题不能归咎于学习者。
5. **按水平评价**：学习目标、曲目难度和评分阈值必须适配学习者水平。
6. **数据权利先行**：代码、权重、公开数据、曲谱和用户录音分别审查。
7. **小模型可控训练**：先有可靠基线和自有授权数据，再微调、蒸馏和部署。
8. **平台边界清楚**：aicloud 管治理和执行；学科插件管领域语义和评价。
9. **质量门禁**：模型不能仅凭厂商 benchmark 或训练 loss 上线。
10. **证据闭环**：每条反馈可追溯到输入、模型/规则版本和评价证据。
